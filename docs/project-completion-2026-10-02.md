# ASUS Control 1.1.4 — перевірка 2026-10-02

Реліз: `com.hermes.pccontrol`, versionName `1.1.4`, versionCode `6`.
APK підписаний тим самим сертифікатом, що й попередня версія. Windows-агент оновлений і запущений з `D:\asus-pc-control\pc-agent\asus-pc-agent.exe`.

## Зміни

- LAN/Tailscale: кешована адреса використовується тільки тоді, коли вона є в поточних налаштуваннях. GET може перейти на резервну адресу після недоступності основної. POST переходить на резервну адресу лише після помилки встановлення з'єднання; неоднозначний тайм-аут або помилка сервера не повторюють команду обладнанню. Автоматичні повтори OkHttp для ПК вимкнені.
- Неповний статус не показує Online; яскравість не підставляється замість відповіді обладнання. Значення поза 0–3 не надсилаються агенту.
- Налаштування MikroTik: міграція старих шаблонів виконується один раз. Наступні збережені користувачем адреса й interface залишаються без підміни. Поля очищуються від пробілів, порти обмежуються допустимим діапазоном.
- OTA: завантаження у тимчасовий файл, перевірка непорожнього й повного завантаження, обмеження частоти повідомлень прогресу, перевірка метаданих релізу та передача дозволу читання системному інсталятору.
- Windows: гібернація приймає лише POST; помилки запису конфігурації не приховуються, порожній токен і недопустимий порт блокують запуск. Існуючий `config.json` не змінений.
- Автозапуск для поточного користувача Windows без підвищення прав. Агент працює в сесії 1; прихований запуск не відкриває вікно консолі.
- Заголовок dashboard вміщується на екрані, системні іконки мають контраст. Відображається фактична адреса підключення. Offline не прирівнюється до підтвердженої гібернації.
- LAN WoL приймає також MAC у форматі `1234.5678.9abc`. HTTPS-клієнт MikroTik використовує TLS.
- `Publish-AndroidRelease.ps1` перевіряє підпис, package ID і відсутність downgrade, зберігає попередні APK у `.release-backups/`, оновлює обидві копії APK та `pc-agent/app-release.json`. Агент читає OTA-версію з цього маніфесту.

## Перевірено

- `go test ./...`: 15 тестів пройшли. `go vet ./...`: без помилок.
- `gradlew.bat testDebugUnitTest assembleRelease`: BUILD SUCCESSFUL; 40 Android-тестів, 0 failures/errors. Release lint також пройшов.
- Сертифікат APK SHA-256: `46aae6ab88acbd30f327a863243e5e4e82dcaca4d73f31081e1301581d0ee3b2`; збігається з попереднім релізом.
- На Android API 35 емуляторі: `adb install -r` поверх 1.1.3 успішний, встановлена 1.1.4 / code 6. MainActivity запустилась, crash log порожній.
- Додаток в емуляторі підключився до реального ASUS через LAN: Online, батарея 100%, яскравість клавіатури 3.
- Кнопка OTA у додатку повернула: «Встановлено актуальну версію (1.1.4, build 6). Оновлень немає.»
- З ASUS перевірені `/api/status` через localhost, LAN `192.168.80.200` і власну адресу Tailscale `100.82.252.86`. Без токена — HTTP 401; GET на endpoint гібернації — HTTP 405.
- `/api/app/version` повертає 1.1.4 / code 6. APK, завантажений з `/app.apk` через адресу Tailscale, збігається за SHA-256 з релізним APK.
- Конфігурація агента й токен збережені; попередні APK та виконуваний файл мають резервні копії.

## Межі перевірки

Фізичний телефон через ADB не підключений, тому встановлення на телефон не виконане. Віддалений доступ з телефону через мобільну мережу не перевірений. Реальний цикл гібернація → Wake-on-LAN і фізичне вимкнення/увімкнення екранів у цьому проході не виконувалися. Автозапуск зареєстрований; новий вхід у Windows не тестувався. Стан екранів залишається запитаним станом, `monitor_state_verified=false`.

## Публікація наступного APK

Після збірки й підпису існуючим ключем:

```powershell
& D:\asus-pc-control\Publish-AndroidRelease.ps1 -ApkPath '<шлях до підписаного APK>' -ReleaseNotes '<опис релізу>'
```

Завантаження через LAN: `http://192.168.80.200:8765/app.apk`.
Завантаження з телефону через підключений Tailscale: `http://100.82.252.86:8765/app.apk`.
